# Audit Analytics Dashboard

Journal-entry testing on general-ledger data (Buchungsdaten), the way auditors
analyse a client's bookkeeping in a financial-statement audit. Load a CSV export
of journal entries and the dashboard flags postings that need a closer look, then
exports them as an Excel exception list.

**Live demo of the results:** see `docs/index.html` (published via GitHub Pages).

## Checks

| Check | What it finds | Why an auditor cares |
|---|---|---|
| Duplicate postings | same vendor, account, amount, date and text twice | double payments – error or fraud |
| Gaps in document numbers | missing numbers in the sequence | completeness: were postings deleted? |
| Weekend & holiday postings | posting dates on Sat/Sun or German public holidays (Baden-Württemberg) | outside normal working time and controls |
| Round amounts | whole multiples of 1,000 € | estimates, manual entries, made-up figures |
| Just below the approval limit | amounts 0–10 % under the limit, counted per user | invoice splitting to avoid a second approval |
| Segregation of duties | entered and approved by the same user | four-eyes principle broken |
| Benford's law | first-digit distribution vs. Benford, overall and per user (Nigrini MAD) | manipulated amounts break the natural pattern |

Most checks are SQL queries on an in-memory SQLite table (`audit_checks/checks.py`);
the date and Benford tests use pandas.

## Data

`data/journal_entries_sample.csv` is **synthetic**: 4,007 postings for fiscal year 2025
with SAP-style field names (BELNR, BUDAT, HKONT, DMBTR, LIFNR, USNAM, …), generated by
`data/generate_sample.py` with known, planted anomalies. Your own CSV needs at least the
columns `BELNR, BUDAT, HKONT, DMBTR, LIFNR, USNAM, FREIGABE`.

## Run it

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/streamlit run app.py          # interactive dashboard
.venv/bin/python -m pytest              # tests: every planted anomaly must be found
.venv/bin/python build_report.py        # rebuild the static page in docs/
```
